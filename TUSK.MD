Техническое задание №1: Инициализация проекта “GameCritic” и развертывание инфраструктуры Frontend

1. Описание и цель задачи

Проект: «GameCritic» — веб-платформа для публикации пользовательских обзоров на видеоигры и ведения геймерских дневников. Цель текущего этапа (Спринт 1): Спроектировать первичную инфраструктуру Django-приложения, развернуть глобальную систему статических файлов и успешно интегрировать JIT-компилятор Tailwind CSS v4 без использования платформы Node.js.

2. Архитектурные требования

2.1. Инициализация рабочей среды

Создать корневую директорию проекта.

Развернуть и активировать изолированное виртуальное окружение Python.

Установить фреймворк Django (версия 5.x) и пакет-обертку pytailwindcss.

Зафиксировать состояние зависимостей в файле requirements.txt.

Сгенерировать базовую структуру проекта. Конфигурационная директория проекта (содержащая settings.py) должна носить семантическое имя config.

2.2. Конфигурация ядра и статики (Урок 2.1)

Развернуть глобальные директории static и templates на корневом уровне проекта.

В файле конфигурации settings.py зарегистрировать директорию глобальных шаблонов в массиве TEMPLATES['DIRS'].

Строго настроить константы для управления статическими файлами:

Назначить сетевой префикс маршрутизатора.

Указать пути к директориям исходной статики (уровень разработчика).

Задать абсолютный путь для папки финальной сборки (уровень production-сервера).

Провести тестовую эмуляцию сборки статики с помощью системной утилиты collectstatic. Убедиться, что папка сборки успешно сгенерирована ядром фреймворка.

Создать файл .gitignore и исключить из индексации виртуальное окружение, базу данных SQLite и сгенерированную директорию сборки статики.

2.3. Интеграция JIT-компилятора Tailwind CSS (Урок 2.2)

Сформировать исходный файл конфигурации input.css внутри глобальной директории статики.

Подключить ядро фреймворка Tailwind и настроить пути сканирования (директивы поиска HTML-шаблонов) с учетом иерархии директорий.

Добавить в конфигурацию несколько пользовательских цветовых переменных (дизайн-токенов), отражающих стилистику платформы видеоигр.

Инициировать фоновый процесс компиляции (режим демона/наблюдателя), который сформирует выходной файл tailwind.css. Скомпилированный файл должен быть готов к подключению в будущие HTML-шаблоны.

3. Требования к визуальному оформлению

Проектирование пользовательского интерфейса (выбор цветовой палитры, типографики и отступов) осуществляется разработчиком самостоятельно. Рекомендуется ориентироваться на стилистику игровой индустрии: использование темных тем оформления, контрастных элементов и строгой сетки. Стилизация должна выполняться исключительно с применением утилитарных классов Tailwind CSS, без написания пользовательских CSS-правил в обход архитектуры фреймворка.

4. Методические указания (Памятка разработчика)

Обратите особое внимание на символ точки (.) при выполнении команды startproject. Это предотвратит создание дублирующихся вложенных директорий.

Константы STATICFILES_DIRS и STATIC_ROOT обязаны указывать на физически разные директории во избежание рекурсивной ошибки копирования.

Во время настройки и тестирования Tailwind CSS у вас должны функционировать два независимых окна терминала (одно для компилятора стилей, второе для локального сервера Django).

Для поиска необходимых CSS-свойств и соответствующих им классов Tailwind активно используйте официальную документацию фреймворка.
